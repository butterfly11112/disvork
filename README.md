# Disvork (Дисворк) — свой чат для друзей

Текстовые каналы, голосовые каналы (WebRTC), личные сообщения, сервера с ролями (владелец/админ/участник),
регистрация только по нику и паролю — без почты.

**Важная особенность:** сервер написан вообще без внешних npm-пакетов — только встроенные модули Node.js
(`node:http`, `node:sqlite`, `node:crypto`). Фронтенд — обычный HTML/CSS/JS без сборки (Vite/React не нужны).
Это значит, что для запуска **не требуется `npm install`** — только сам Node.js версии 22.5 или новее.

## Структура проекта

```
disvork/
  server/
    src/
      index.js     — HTTP-сервер, раздаёт API и статику фронтенда
      api.js        — все REST-эндпоинты + realtime через Server-Sent Events
      db.js         — схема SQLite (node:sqlite)
      auth.js        — подписанные токены авторизации (без внешних JWT-библиотек)
      password.js    — хеширование паролей (scrypt из node:crypto)
      bus.js         — рассылка событий подключённым клиентам + голосовые комнаты
      router.js      — минимальный HTTP-роутер
      id.js          — генерация id и инвайт-кодов
  public/
    index.html, style.css, app.js  — весь фронтенд, без сборки
```

## Запуск локально

Нужен **Node.js 22.5+** (лучше 22.x LTS свежее). Проверить версию: `node -v`.

```bash
cd server
node src/index.js
```

Откройте http://localhost:4000 — сразу увидите экран регистрации.
База данных SQLite создастся автоматически в `server/data.sqlite`.

По умолчанию сервер слушает порт `4000` — можно поменять переменной окружения `PORT`.

**Обязательно перед реальным использованием с друзьями** задайте свой секрет для подписи токенов
(иначе используется предсказуемый секрет по умолчанию):

```bash
export AUTH_SECRET="замени-на-любую-длинную-случайную-строку"
node src/index.js
```

## Что уже есть

- Регистрация/вход по нику и паролю (без почты), пароли хранятся хешированными (scrypt).
- Сервера (гильдии): создание, приглашение по коду, роли — владелец / админ / участник.
- Текстовые каналы с историей сообщений и обновлением в реальном времени.
- Личные сообщения между пользователями.
- Голосовые каналы: подключение/отключение, мьют микрофона, звонок идёт напрямую между
  браузерами участников (WebRTC), сервер только помогает договориться о соединении (сигналинг).
- Права: только владелец и админы могут создавать/удалять каналы, выдавать роль админа и
  исключать участников (кроме владельца).

## Чего нет (и как расширить)

Это рабочий MVP, а не полная копия Discord. Дальше можно добавить: аватарки-картинки (сейчас только
цветной кружок с инициалами), редактирование/удаление сообщений, реакции, загрузку файлов, видео в
голосовых каналах (в WebRTC-часть легко добавить видеотрек), уведомления/непрочитанные, поиск по
сообщениям, мобильную адаптацию интерфейса.

## Как выложить в интернет, чтобы друзья заходили по ссылке

Приложению нужен **обычный постоянно работающий сервер** (не «serverless»), потому что:
- используется SQLite-файл на диске (должен сохраняться между запросами);
- голосовые каналы и чат держат постоянное соединение (Server-Sent Events).

Так что варианты вроде Vercel/Netlify (для статики и serverless-функций) не подойдут напрямую.
Нужен вариант, где можно просто запустить `node src/index.js` и он будет работать постоянно.

### Вариант 1 — свой VPS (самый надёжный и гибкий)

Подойдёт почти любой недорогой VPS (Timeweb Cloud, VDSina, Hetzner, DigitalOcean и т.д.) с Ubuntu.

1. Арендуйте VPS, зайдите по SSH.
2. Поставьте Node.js 22+:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash -
   sudo apt-get install -y nodejs
   node -v   # должно быть 22.5 или новее
   ```
3. Загрузите папку `disvork` на сервер (например, через `scp` или `git`).
4. Запустите через pm2, чтобы сервер поднимался автоматически и работал в фоне:
   ```bash
   sudo npm install -g pm2
   cd disvork/server
   export AUTH_SECRET="ваш-секрет"
   pm2 start src/index.js --name disvork
   pm2 save
   pm2 startup   # добавит автозапуск после перезагрузки сервера
   ```
5. Чтобы друзья заходили по-человечески (с доменом и HTTPS, что важно — без HTTPS браузер
   не даст доступ к микрофону для голосовых каналов на "чужом" домене), поставьте Caddy —
   он сам получит бесплатный SSL-сертификат:
   ```bash
   sudo apt install -y caddy
   ```
   В `/etc/caddy/Caddyfile`:
   ```
   ваш-домен.ru {
       reverse_proxy localhost:4000
   }
   ```
   ```bash
   sudo systemctl restart caddy
   ```
   Направьте A-запись домена на IP вашего VPS — и всё, друзья заходят на `https://ваш-домен.ru`.

   Без домена (по IP) браузер обычно блокирует доступ к микрофону на HTTP — тогда голосовые
   каналы работать не будут, а текстовый чат будет.

### Вариант 2 — Railway / Render (быстрее всего, без своего сервера)

Такие платформы дают постоянно работающий контейнер (не serverless) и сами выдают HTTPS-домен.

1. Зарегистрируйтесь на Railway.app или Render.com, привяжите GitHub-репозиторий с этим проектом
   (или загрузите проект туда, как они предложат).
2. Команда запуска: `node src/index.js`, рабочая директория — `server`.
3. **Важно:** подключите постоянный диск (persistent volume/disk) под путь, где лежит `data.sqlite`
   (например, смонтируйте его в `server/` и укажите `DB_PATH=/data/data.sqlite`), иначе база будет
   стираться при каждом передеплое.
4. Задайте переменную окружения `AUTH_SECRET` — свою случайную строку.
5. Платформа даст вам `https://...` ссылку — это и есть адрес вашего чата.

### Общее для всех вариантов

- Обязательно задайте свой `AUTH_SECRET` (переменная окружения) — иначе кто угодно сможет
  подделать токен входа.
- HTTPS обязателен для работы голосовых каналов (браузеры не дают доступ к микрофону без него) —
  и Caddy (вариант 1), и Railway/Render (вариант 2) выдают SSL автоматически.
- Регулярно делайте резервную копию файла `server/data.sqlite` — это вся ваша база (пользователи,
  сообщения, сервера).

Если решите, на каком варианте остановиться (свой VPS или Railway/Render) и какой домен использовать —
могу подробнее расписать шаги именно под него.
